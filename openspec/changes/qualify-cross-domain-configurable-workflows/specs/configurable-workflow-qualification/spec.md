## ADDED Requirements

### Requirement: Full contract and performance acceptance

Qualification SHALL cover every declared VCL/storage/import/adapter method and acceptance A01–A66, with dense-table baseline performance and optional-feature overhead measured separately; a demonstration slice SHALL NOT qualify the complete platform.

#### Scenario: Ordinary table benchmark
- **WHEN** the workload uses no temporal relations/history
- **THEN** equivalent typed-table baseline, plans, rows examined and measured overhead are reported and failing gates block release

#### Scenario: Contract examples pass grammar
- **WHEN** the target JSON examples validate structurally
- **THEN** semantic compiler, source capabilities, security and runtime outcomes still require independent tests

#### Scenario: Partial milestone
- **WHEN** only a native table and one alert are demonstrated
- **THEN** complete-platform acceptance remains open


### Requirement: Demonstrated reusable semantics

Qualification SHALL show multiple domain workflows and held-out schemas using shared operators without scenario-specific evaluator branches.

#### Scenario: Third domain
- **WHEN** a new customer workflow reuses already supported primitives
- **THEN** it is configured through ordinary APIs/AI without a new core handler

#### Scenario: Missing primitive
- **WHEN** a held-out task requires an unsupported operator
- **THEN** the assistant reports the capability gap instead of inventing success

### Requirement: Independent quality and resilience

Acceptance SHALL grade exact persisted resources, temporal evidence, access isolation and complete-task outcomes with first-pass/recovery/economic accounting.

#### Scenario: Schema-valid wrong plan
- **WHEN** the model chooses the wrong relation, field or subject
- **THEN** the task fails despite valid output schema

#### Scenario: Unknown evidence
- **WHEN** work intervals or event coverage are incomplete
- **THEN** the expected result remains unknown and does not produce an unsupported violation



### Requirement: Independent revision two qualification

Qualification SHALL cover A01-A66 through runtime evidence and distinguish documentation conformance from actual compiler, database, recovery and provider quality acceptance.

#### Scenario: Revision two implementer boundary
- **WHEN** documentation grammar and semantic fixtures pass without runtime implementation
- **THEN** no runtime task or platform release gate is marked complete from that result

### Requirement: Cross-domain delegated knowledge acceptance

Configurable workflow qualification SHALL include AI01-AI24 and A01-A66 across manual and AI entry paths; source evidence SHALL NOT replace current owner data or authorization.

#### Scenario: Consultation and retrieval boundary
- **WHEN** a retrieved document conflicts with user policy or an old source revision
- **THEN** the system reports CONFLICT/STALE, preserves exact required context and cannot silently activate an inferred business rule

### Requirement: Dependency and semantic correctness beyond envelope grammar

Cross-domain qualification SHALL cover AI01-AI24, including dependency rebase, policy applicability, exact requirement-to-effect mappings, private retrieval hydration and absolute plan deadline behavior.

#### Scenario: Revision two dependency and quality boundary
- **WHEN** all documentation examples pass while runtime oracle cases remain unexecuted
- **THEN** the platform remains unqualified and no runtime task is checked from documentation results

### Requirement: Shared Spring pipeline acceptance

Cross-domain acceptance SHALL prove that every supported skill uses the same guarded exchange, current authorization, durable scheduler and reviewed owner-effect boundary. Passing annotations/schema checks SHALL NOT substitute for real ApplicationContext/provider/DB integration evidence.

#### Scenario: Spring extension boundary
- **WHEN** the same configurable workflow is authored through different domain skills or recovered after a worker crash
- **THEN** SPR01-SPR15 plus the applicable AI01-AI24/A01-A66 demonstrate identical authority, replay, observability and exact persisted effects

### Requirement: Raw source to business outcome qualification

Bus qualification SHALL include BUS01-BUS10 and a concrete source-to-canonical binding trace before claiming complete-task success; synthetic enriched VCL inputs alone SHALL NOT qualify raw HSL support.

#### Scenario: Original bus request boundary
- **WHEN** an example graph receives a preassigned occurrenceId or retained2s synthetic fixtures pass
- **THEN** source capture/identity integration and original-request door semantics remain independently required and old scores are not rewritten
