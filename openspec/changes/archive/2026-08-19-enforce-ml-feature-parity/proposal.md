# Enforce ML Feature Parity

## Why

Feature snapshots and online inference payloads now share a contract, but the
offline generator and online feature vector path are still implemented in
separate places. A matching schema hash is not enough if transformations drift
semantically.

Production model serving needs a hard parity gate: for the same device,
timestamp, template, family, and horizon, offline feature rows and online
feature vectors must be generated by shared contract logic or verified as
equivalent.

## What Changes

- Add feature parity fixtures and tests comparing offline snapshot rows to
  online inference feature vectors.
- Promote feature generator version/template/horizon into compatibility checks.
- Return explicit incompatibility when online features are generated by a
  different contract or transformation version than the selected model expects.
- Add diagnostics for missing, mismatched, or semantically incompatible
  features.
- Update docs for the feature contract and parity verification path.

- Existing fallback behavior remains.
- Incompatible online features become explicit fallback/unavailable statuses
  instead of silent scoring.
