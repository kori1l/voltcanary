# Исследование оптимизации загрузки и отрисовки дашбордов

## Why

Дашборды объединяют много виджетов и источников данных. Требуется проверить,
не растут ли HTTP/SQL обращения по схеме N+1, не загружается ли больше данных,
чем используется, и не теряется ли готовый интерфейс во время обновления.
Наличие этих проблем пока не подтверждено измерениями.

## What Changes

- Провести воспроизводимый аудит браузера, dashboard-service, downstream-сервисов
  и SQL с разделением времени ожидания данных и стоимости отрисовки.
- Проверить N+1, дублирование, лишние данные и стандартные возможности оптимизации
  запросов, кеширования, базы данных, доставки JS и React/графиков.
- Исследовать сохранение отрисованного дашборда при повторном открытии и обновлении,
  постепенное заполнение виджетов и каркас при первом входе вместо общего Loading.
- Подготовить доказательный отчёт и приоритизированный список необходимых
  оптимизаций с рекомендуемой реализацией, альтернативами и критериями проверки.

Это исследовательский change. Его выполнение не включает внедрение оптимизаций,
изменение API/схем, добавление индексов, зависимостей или продуктового кеша.
Проверенные рекомендации становятся основанием для отдельных implementation changes.

## Impact

- Новая capability: `dashboard-optimization-research` — требования к исследованию,
  а не обещание уже оптимизированного продукта.
- Область анализа: frontend dashboard routes/viewer/editor/query hooks и charts;
  backend dashboard query scheduler/evidence adapters; device, telemetry,
  analytics, alert, identity/workspace reads и их SQL по фактическому маршруту.
- Результат: `docs/current/flows/dashboard-optimization-research.md` с обновлением
  ближайшего индекса документации; локальные трассы в игнорируемых `artifacts/`.
- Existing source contracts: `dashboard-widget-queries`, `console-data-state-semantics`,
  `private-dashboard-domain`, `team-dashboard-publication`.
- Исследование сохраняет авторизацию, полные знаменатели агрегатов, единицы,
  временной контекст, ограничения объёма, свежесть и независимость ошибок виджетов.

## Definition Of Done

Отчёт содержит базовые измерения, заполненный чеклист, подтверждённые проблемы
и ограничения проверки, варианты загрузки без общего Loading и план оптимизаций.
Каждая рекомендация связана с доказательствами и проверяемым целевым эффектом.
Проверенные нормальные участки также перечислены; неизвестное не объявляется нормой.
