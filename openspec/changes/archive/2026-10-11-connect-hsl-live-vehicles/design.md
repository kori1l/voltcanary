# Design

The connector lives in `deploy/connectors/hsl`, enabled by an optional Compose overlay/profile. A pinned Paho Python client subscribes with verified TLS to ongoing VP tram topics for an explicit allowlist of at most 20 vehicles. Discovery for initial setup uses the public tram subscription, then pins topic operator/vehicle identities (initially three, expanded to ten at the user's request). Increasing Count appends active vehicles while preserving the existing allowlist; shrinking is refused. Setup recreates the subscriber to apply private configuration. MQTT topic operator is authoritative: payload oper can differ for subcontracting.

Each source is API/REST, external ID `hsl-tram-OOOO-VVVVV`. The device is VEHICLE with real-feed metadata and HSL attribution. Provisioning is owner authenticated and idempotent by external identity, reuses existing source tokens from private local configuration, and refuses incompatible or ambiguous objects. Owner passwords/JWTs are never persisted. Source tokens are written only to ignored `docker-data/hsl/config.json`, read-only mounted into the connector.

Map VP lat/long to latitude/longitude, spd m/s to speedKmh, hdg 360 to zero; use tst unchanged in meaning. Accept GPS observations only (`loc=GPS`), valid coordinates, UTC offset timestamps no older than 120 seconds or more than 15 seconds ahead, finite optional speed/heading in supported ranges. Omit unknown optional values. Do not import HSL odo (a unreliable trip counter), fuel or ignition. Retained MQTT messages are ignored.

Callback work is decoding/validation/coalescing only. One latest pending observation per configured vehicle bounds memory. A separate worker forwards at most one position per vehicle every five seconds with that source's bearer token to ordinary ingestion. Newer timestamps replace pending samples; old/duplicate timestamps are skipped. On transient HTTP failure retain the latest fresh sample for retry; unauthorized/removed sources are logged without secrets. No invented interpolation or timestamp refresh on outage. Existing map stale semantics apply. Loss during outages is explicit: there is no durable queue/backfill.

MQTT reconnect uses bounded exponential delays and resubscribes. Status file includes connection state, accepted count, last accepted time, pending count and heartbeat, never credentials. Compose healthcheck detects absent/stale heartbeat or MQTT disconnection. Shutdown stops network loop and worker. Initial dashboard has one fixed map widget per selected vehicle with Europe/Helsinki time context; fleet page also discovers these devices.

The user requested one common dashboard map. Extend existing vehicle-map queries with optional `vehicleSources` (UUID-to-source map, exact fixed binding, at most 20). A typed internal position request accepts either the original single target or the fleet list; signed scope authorization precedes all source validation and latest reads. Dashboard responses contain `positions.fleet`; a focused frontend component maps evidence into the existing FleetMap without its own fetch/timer. Runtime restrictions filter sources, and shared definitions hide unauthorized source identifiers. Fleet mode reads only latest positions; individual movement/history pages retain trails and playback. A reused demo dashboard retains its old revisions when quota prevents another dashboard.
