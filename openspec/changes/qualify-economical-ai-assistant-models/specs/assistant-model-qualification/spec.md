## ADDED Requirements

### Requirement: Configurable cross-domain model evidence

Qualification of new configurable skills SHALL include held-out schemas, exact VCL/owner outcomes, direct customer data capabilities, strict import rejection and remote UNKNOWN recovery while retaining all original critical first-pass/recovery gates and unchanged historical reports.

#### Scenario: Cheap invalid solution
- **WHEN** a low-cost model produces schema-valid work logic using vehicle motion as confirmed employee work
- **THEN** the task fails its independent semantic oracle

#### Scenario: Incomplete evidence
- **WHEN** an adapter or model profile is unavailable
- **THEN** the affected trial is blocked/incomplete and cannot qualify the declared capability or economics



### Requirement: Independent economical-model qualification
Each enabled economical skill/model profile SHALL meet predeclared independent task-quality and full-pipeline economic gates using comparable versioned configurations and rates, with failed attempts included in cost reporting.

#### Scenario: Several cheap calls
- **WHEN** a decomposed pipeline uses planner, step and repair calls
- **THEN** their complete cost is compared with the fixed reference under the same successful-task definition

#### Scenario: Correction improves the final result
- **WHEN** an initial candidate fails but a later repair completes the task
- **THEN** initial quality remains failed for that original trial, recovery/final success are reported separately and every planner/context/generator/repair/assessment call is included without changing denominators

#### Scenario: First-pass diagnostic profile
- **WHEN** core model quality is measured before resilience is added
- **THEN** automatic corrections and model judges are disabled, basic schema/access/confirmation checks remain active and independent post-run grading does not alter the generated candidate or hide rejected/unreached results

#### Scenario: Unavailable price
- **WHEN** usage or comparable reference pricing is unknown
- **THEN** the result does not claim proven savings

#### Scenario: Weak interpretation
- **WHEN** a cheap model returns valid JSON for the wrong widgets
- **THEN** independent outcome checks fail the task regardless of format correctness

#### Scenario: Conversational continuity
- **WHEN** the frozen corpus exercises a completed device plan followed by a dashboard request, a short reply after reload, two-device ambiguity and edits before and after dashboard creation
- **THEN** independent checks assert the intended receipt-backed identity, correct answer interpretation, clarification when needed and same-dashboard updates after creation, with every actual model call included in cost

### Requirement: Measured portability and bounded rollout
Verified provider portability SHALL require passing the same canonical skill and outcome contracts on actual different-provider configurations; all live campaigns SHALL respect declared budgets and opt-in controls.

#### Scenario: Different provider
- **WHEN** an adapter uses JSON text instead of native tools
- **THEN** the same domain skill and checks apply and any format repair counts toward cost

#### Scenario: Provider unavailable
- **WHEN** a required second-provider trial cannot run
- **THEN** portability remains incomplete and no result is fabricated

#### Scenario: Budget reached
- **WHEN** the live campaign reaches its predeclared ceiling
- **THEN** further calls stop and the campaign remains incomplete rather than being silently extended

#### Scenario: Release
- **WHEN** v2 default enable is requested
- **THEN** legacy compatibility, quality, preservation/access, browser and economic gates must all have supporting evidence
- **AND** every supported natural-language scenario in the parity matrix uses v2 skills without semantic regex routing; temporary legacy-only generation cannot be counted as completed migration

### Requirement: Independent clarification and retrieval quality evidence

Model qualification SHALL include the independently labelled AI01-AI24 cases, compare exact owner outcomes and retrieval relevance separately, and include all chat/embedding/rerank/indexing calls and unknown costs. Existing frozen gates SHALL NOT be relaxed.

#### Scenario: Consultation and retrieval boundary
- **WHEN** nested delegation or RAG improves a final answer after a failed first candidate
- **THEN** reports retain the first failure, all costs and late/cancelled outcomes without asserting production qualification from grammar tests

### Requirement: Predeclared independent quality and ablation gates

Qualification SHALL use a completed campaign manifest, independent goal/evidence labels and controlled single-skill/delegation/RAG/reranker ablations with all attempted tasks and unknown costs retained. Existing stronger frozen gates SHALL prevail.

#### Scenario: Revision two dependency and quality boundary
- **WHEN** a configuration adds agents, retrieval, or a different model snapshot
- **THEN** the new tuple is separately qualified for eligible roles/languages; a schema pass or higher final score without the prescribed quality/cost/latency gates cannot enable it

### Requirement: Framework integration evidence before model quality claims

Qualification SHALL retain SPR01-SPR15 framework evidence independently from AI01-AI24 model/semantic gates. Instrumentation SHALL not double count billing, hide retry attempts or change frozen task denominators.

Qualification snapshots SHALL pin library, engine, graph-definition and checkpoint-format versions. Offline library adoption and supported-scope integration SHALL NOT close full A6 acceptance or transfer historical model-quality results to a new engine without the required qualification.

#### Scenario: Spring extension boundary
- **WHEN** Spring AOP/advisor fixture tests pass without independent live model/business outcome evidence
- **THEN** only framework integration is qualified; no model/default-enable claim or completed runtime task is inferred
